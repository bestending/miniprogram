# 开发排期表

> 基于 15 个 ADR(业务 8 + 技术 4 + 细化 3)拆解。以 **1 个全栈开发**为基准估算,实际按团队规模并行加速。

## 一、排期总览

| Phase | 模块 | 工期(人天) | 优先级 | 依赖 |
|---|---|---|---|---|
| **0** | 基础设施 | 3 | P0 | — |
| **1** | 认证与数据层 | 4 | P0 | Phase 0 |
| **2** | 核心业务云函数 | 6 | P0 | Phase 1 |
| **3** | 顾客端小程序 | 8 | P0 | Phase 2 |
| **4** | 管理端小程序 | 7 | P1 | Phase 2 |
| **5** | 提现与支付 | 3 | P1 | Phase 2, 4 |
| **6** | 测试与上线 | 5 | P0 | Phase 3-5 |
| | **合计** | **36 人天** | | |

> **并行加速**:2 人团队(1 前端 + 1 后端)可将 Phase 3+4 并行,总工期压到约 22 人天。

## 二、模块依赖关系

```
Phase 0 基础设施
  ├─→ Phase 1 认证与数据层
  │     ├─→ Phase 2 核心业务云函数
  │     │     ├─→ Phase 3 顾客端小程序 ──┐
  │     │     ├─→ Phase 4 管理端小程序 ──┤
  │     │     └─→ Phase 5 提现与支付 ────┤
  │     │                                 ↓
  │     └───────────────────────→ Phase 6 测试与上线
```

## 五、风险与缓冲

| 风险 | 影响 | 缓冲方案 |
|---|---|---|
| 微信小程序审核 1~3 天 | M5 延期 | 提前 3 天提交审核,预留缓冲 |
| 订阅消息模板审批 1~3 天 | Phase 2.3 阻塞 | Phase 0 阶段提前申请模板 |
| 微信支付商户号开通 3~5 天 | Phase 5 阻塞 | Phase 0 阶段提前提交资质 |
| 云函数冷启动 200~500ms | 用户体验 | 首期接受,日活 1k 后评估(见 ADR-0009) |
| Vant 组件样式冲突 | Phase 3-4 返工 | 预留 1 天样式调试缓冲 |

## 六、建议执行顺序

```
第 1 周:Phase 0 + Phase 1            → M1
第 2 周:Phase 2                       → M2(核心返利跑通)
第 3 周:Phase 3(顾客端)              → M3(顾客端可体验)
第 4 周:Phase 4(管理端)              → M4(管理端可体验)
第 5 周:Phase 5(提现与支付)           → M4 完整
第 6 周:Phase 6(测试与上线)           → M5(正式上线)
```

> 以上周数以 1 个全栈开发为基准。2 人团队可压缩至 4 周。
