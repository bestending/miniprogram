# ADR-0009: 整体技术栈选型

## Status
Accepted

## Date
2026-09-18

## Context
业务建模已完成 8 个 ADR,需要确定落地的技术栈。决策涉及三个互相耦合的维度:后端语言、部署形态、小程序端框架。候选权衡如下。

### 后端语言
- (a) Node.js / TypeScript
- (b) Python / FastAPI
- (c) Go / Gin
- (d) Java / Spring Boot

### 部署形态
- (a) 微信云开发(云函数 + 云数据库 + 云存储)
- (b) 自建云主机 + Docker
- (c) SaaS 多租户
- (d) 混合

### 小程序框架
- (a) 微信原生 + TypeScript + Vant Weapp
- (b) Taro 3.x(React)
- (c) uni-app(Vue)
- (d) 纯原生(无 UI 库)

## Decision
确定三件套如下,三者强耦合,不可单独更换:

- **后端**:**Node.js 20 LTS + TypeScript 5**(`@cloudbase/cli` 云函数运行时)
- **部署**:**微信云开发**(云函数 + 云数据库 + 云存储 + 云调用)
- **小程序**:微信原生 + TypeScript + **Vant Weapp 1.x** + miniprogram-api-typings

理由:
- Node.js 与小程序 TS 同语言,代码可复用(类型定义、`fetch` 工具、数据校验器)
- 云开发免运维、按量计费,与单店小业务体量匹配(成本上限可控)
- 原生 + Vant Weapp 是双小程序最稳的组合,不引入多端抽象层,避免调试链路绕弯

## Consequences
- (+) **首期交付最快**:云开发 0 运维,1 个云函数 + 1 套集合即可跑通邀请码核销
- (+) **微信支付 / 客服消息 / 用户体系**:通过云调用一行 `cloud.openapi.payment.xxx` 完成,不需要自维护 access_token
- (+) **按量计费**:返利计算 / 通知回调都是偶发调用,空闲时不花钱
- (+) **TS 全栈共用类型**:邀请码 `RebateCode`、订单 `Order`、用户 `Profile` 等类型定义放 `packages/shared`,双端零成本同步
- (-) **数据库是文档型(类 MongoDB)**:不能像 MySQL 那样做 JOIN / 事务聚合,需要冗余字段或在云函数里手动聚合
- (-) **云函数冷启动**:首次调用有 200~500 ms 延迟,需要预热(定时 ping)或接受
- (-) **锁死在微信生态**:未来要做支付宝/抖音/H5 端必须重写,原生框架扩展性差
- (-) **云开发资源额度**:免费版有调用次数与数据库容量上限,日订单 1w+ 时需要升级

## Known Risks
- **店主审核自己提现**:见 ADR-0007,首期接受,后续追加规则
- **云开发数据库事务能力**:跨集合事务能力有限(2024 年后才逐步完善),返利状态机需要谨慎设计(已用「待定金额字段」+「最终核销」两步走规避)
- **冷启动**:可放一个每 5 分钟 ping 一次的定时触发器

## 微信平台限制兼容性矩阵(2026-09-18 确认)

> 以下 7 个微信平台限制已逐个评估并确认处理方案,实施时按此执行。

| # | 平台限制 | 影响 | 选定方案 | 落点 ADR |
|---|---|---|---|---|
| 1 | 云开发定时触发器免费版 50 次/日 | `heartbeat-ping` 每 5 分钟一次 = 288 次/日,严重超限 | **暂不修改设计,首期用方案 (a) 去掉 heartbeat 接受冷启动;日活过 1k 后评估升级付费版** | [ADR-0015](file:///d:/demo/docs/adr/0015-scheduler-and-reconciliation.md#L45-L53) |
| 2 | 微信订阅消息「一次性订阅 1 条」 | 每次返利到账即推会撞限制 | **每日推送上限 N=1(店主可调)+ 关键事件(提现/过期)豁免 + 站内消息中心兜底** | [ADR-0014](file:///d:/demo/docs/adr/0014-notification-strategy.md) |
| 3 | `wx.getPhoneNumber` 必须用户主动点按钮 | 不能自动弹窗,影响注册流畅度 | **邀请码注册环节一次性完成**(扫码 → 注册页一个 button 同时触发微信授权 + 手机号授权 → 绑定成功) | [ADR-0013](file:///d:/demo/docs/adr/0013-auth-and-permissions.md#L56-L68) |
| 4 | 微信支付企业付款 API 单日单用户默认 2 次 | 提现频次受微信侧限制 | **接受默认 2 次/天**(我们的「月 100 元上限」更严,实际不冲突) | ADR-0005 |
| 5 | 云函数免费版单次执行 ≤ 20s | T+7 批量计入 > 1000 单会超时 | **分批处理,每批 500 单**(云函数内 for 循环,超时自动续跑下一批) | ADR-0015 |
| 6 | 小程序主包 ≤ 2MB | Vant 全量引入会超 | **按需引入 Vant + 分包加载**(主包控制在 1.5MB 以内,二级页面放分包) | ADR-0011 |
| 7 | 云开发免费版数据库 2GB | 日活 5k+ 可能触顶 | **接受 2GB,后期再评估升级**(首期 1k 日活 ≈ 500MB,足够) | ADR-0010 |

### 付费版升级触发条件(预警线)

| 指标 | 阈值 | 触发动作 |
|---|---|---|
| 日活顾客 | > 1,000 | 评估定时触发器 + 数据库容量 |
| 日订单峰值 | > 1,000 | 评估云函数单次时长 |
| 月活顾客 | > 5,000 | 数据库必触顶,必须升级 |
| 月返利支出 | > 10,000 元 | 评估提现频次,申请调高企业付款单日次数 |
