# ADR-0006: 双小程序架构(顾客端 + 管理端)

## Status
Accepted

## Date
2026-09-18

## Context
店主运营后台需要支持节假日日历可视化、提现审核、数据看板等重操作。Q(S1) 答为 **c(独立管理小程序)**,放弃 H5 内嵌方案,放弃 PC Web 后台。

## Decision
采用**双小程序**架构:
- **顾客端小程序**(已存在):顾客下单、领取邀请码、查看余额、申请提现
- **管理端小程序**(新建):店主与店员运营后台,包括节假日日历配置、提现审核、数据看板

两者**共享同一微信开放平台主体**,通过 `unionID` 打通账号:店主本人若同时是顾客(作为邀请人),其在两端是同一个 unionID,可自然关联身份。

代码组织:两个小程序用同一前端框架,放在同一 monorepo,共享组件库与 API SDK。

## Consequences
- (+) 完整原生体验,日历组件、tabBar、订阅消息、客服会话全部支持
- (+) 与顾客小程序解耦,升级互不影响
- (+) unionID 打通后,店主本人作为顾客时身份自然衔接
- (-) 第二个 appid 需要单独注册、独立上架审核
- (-) 两个小程序分别维护,即使 monorepo 也需要独立打包配置
- (-) 节假日配置等低频更新发版流程长(微信审核 1–3 天)
