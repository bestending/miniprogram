# ADR-0014: 通知与触达

## Status
Accepted

## Date
2026-09-18

## Context
返利系统的「触达」决定了顾客是否感知到自己的收益,直接影响留存与口碑。需要在三个维度选型:

### 主通知通道
- (a) 微信客服消息(48 小时窗口)
- (b) **微信订阅消息** ← 已选
- (c) 短信
- (d) 仅站内消息中心

### 推送频次
- (a) **每次返利到账即推** ← 已选
- (b) 每日汇总
- (c) 仅推重要事件
- (d) 店主可调

### 已知设计冲突

微信订阅消息**有「一次性订阅」限制**:
- 用户每次点授权,可发 1 条消息
- 「长期订阅」仅对政务、医疗等特殊类目开放,**餐饮不在范围内**

这意味着若严格执行「(a) 即每次返利到账即推」+「(b) 订阅消息」,每条返利都需要顾客主动点授权——体验差。

## Decision

### 主通道:微信订阅消息 + 站内消息中心兜底

| 通道 | 用途 | 频次 |
|---|---|---|
| **微信订阅消息** | 重要事件推送(返利到账 / 提现审核结果 / 即将过期) | 用户已授权时 |
| **站内消息中心** | 全部事件流水 | 不限 |

### 解决订阅消息「1 条限制」的方案

1. **顾客首次进余额页**:引导弹窗「开启返利到账提醒」(本质是一次性订阅)
2. **返利到账事件触发**:
   - 若用户已订阅 → 立即推送
   - 若未订阅 → 仅写站内消息
3. **每日上限保护**:顾客当日已被推送 N 条后(默认 N=1,可配),其余事件只进站内
4. **店主可调阈值**:管理端配置项「每日推送上限」,店主可设为 1/2/3/不限
5. **特殊事件豁免**:提现审核结果 + 即将过期(余额 90 天)不计入 N 上限

### 通知事件清单(15 类)

| 事件 | 推送通道 | 是否计入每日上限 | 模板 ID(待申请) |
|---|---|---|---|
| 邀请码被领 | 站内 | — | — |
| 邀请码被核销 | 站内 | — | — |
| 返利计入待定(T+7 倒计时) | 站内 | — | — |
| **返利到账** | 订阅 | ✓ | `REBATE_CREDITED` |
| 提现申请已提交 | 订阅 | ✓ | `WITHDRAW_SUBMITTED` |
| **提现审核通过 / 已打款** | 订阅 | ✗(豁免) | `WITHDRAW_APPROVED` |
| 提现审核被拒 | 订阅 | ✗(豁免) | `WITHDRAW_REJECTED` |
| **即将过期(到期前 7 天)** | 订阅 | ✗(豁免) | `BALANCE_EXPIRING` |
| 店主节假日活动开始 | 订阅 | ✓ | `HOLIDAY_START` |
| 顾客绑定手机号成功 | 站内 | — | — |
| 同设备硬互斥警告 | 站内 | — | — |
| 当月提现上限已达 | 站内 | — | — |
| 月榜 TOP10 | 站内 | — | — |
| 客服消息回执 | 站内 | — | — |
| 系统异常 / 退款自动扣回 | 站内 | — | — |

### 订阅消息模板(示例,需微信公众平台申请)

**REBATE_CREDITED**(返利到账):
```
{{title}} 
您的邀请奖励已到账 ¥{{amount}} 元
点击查看明细
```

**WITHDRAW_APPROVED**(提现审核通过):
```
{{title}}
¥{{amount}} 元提现已成功打入您的微信零钱
微信支付凭证查看
```

**HOLIDAY_START**(节假日活动开始):
```
{{title}}
{{holidayName}} 返利活动已开启
活动期内被邀请人下单,返利比例提升至 {{rate}}%
```

### 实现落点

- **触发位置**:全部在云函数内调用 `cloud.openapi.subscribeMessage.send`
- **频次控制**:在 `daily_push_counters` 集合按 `(customerId, date)` 计数,事务写
- **跳过授权失败**:若 `errCode === 43101`(用户拒收)/ `errCode === 40037`(模板失效),写 audit_log + 静默降级到站内

## Consequences
- (+) **关键事件不漏**:返利到账 + 提现审核结果 + 即将过期均有推送
- (+) **用户体验好**:未授权不会被骚扰,授权后也仅每日上限 N 条
- (+) **店主可控**:每日上限可调,平衡获客骚扰
- (+) **降级路径清晰**:订阅失败 → 站内消息,不会丢事件
- (-) **微信订阅消息需提前申请模板**:5 个模板,审核需 1~3 天
- (-) **需要每用户当日推送计数**:增加 1 张集合与事务写
- (-) **首次进余额页会弹授权窗**:少数用户会拒,需要文案引导

## Known Risks
- **微信订阅模板审批被拒**:极端情况微信收紧模板政策,需要回退方案(全部站内消息)
- **每日上限 N=1 太严**:活跃顾客会漏掉部分事件——可在管理端给店主建议值 1~3
- **消息内容合规**:不能用「返利」等敏感词组,模板中需用「奖励」等替代,需提前与法务/微信审核对齐
